# 대규모 유저 모수 측정 성능 한계 극복: Redis Bitmap 활용

## 1. 문제 (Problem)

### 서베이 타게팅의 모수 산출 성능 저하

"돈 버는 서베이" 서비스에서 어드민이 특정 태그 조건을 조합하여 설문 대상자(패널) 규모를 예측할 때 성능 문제가 발생했습니다.

- **데이터 구조**: `패널 (1:N) - 패널태그 (N:1) - 태그` 구조로 매핑되어 있어서 특정 태그를 기준으로 사용자를 찾는 역방향 조회는 성능이 저하되었습니다.
- **성능 임계치 도달**: 유저 수가 수백만 명을 넘어서면서 복잡한 `AND/OR` 조건으로 모수를 집계하는 SQL 쿼리가 인덱스만으로 버티지 못하고 타임아웃을 유발했습니다.
- **실시간성 요구**: 어드민에서 타게팅 조건을 바꿀 때마다 실시간으로 예상 모수를 즉시 확인할 수 있어야 했습니다. (계약 시 비용 측정을 위해)

## 2. 전략 (Strategy)

### Redis Bitmap을 이용한 역인덱싱(Reverse Indexing) 구축

수백만 명의 유저 데이터를 비트(Bit) 단위로 압축하고, Redis의 비트 연산을 통해 고성능 세트 연산을 수행하도록 구조를 개편했습니다.

1.  **Bit Mapping**: 각 유저의 고유 ID를 비트맵의 오프셋(Offset)으로 매핑합니다. (예: 100만 유저는 약 125KB의 비트맵으로 표현 가능)
2.  **Tag-based Bitmap**: 각 태그 ID를 키(Key)로 하는 개별 비트맵을 생성합니다. (`tag:1001`을 가진 유저들의 비트만 1로 설정)
3.  **Tag 조합 연산 (BITOP)**: 여러 태그가 조합된 타게팅 조건(`A 태그 AND B 태그`)을 Redis의 `BITOP` 명령어로 연산하여 결과 비트맵을 생성합니다.
4.  **모수 측정 (BITCOUNT)**: 최종 결과 비트맵에서 1로 설정된 비트의 개수를 `BITCOUNT`로 즉시 파악하여 모수를 산출합니다.

## 3. 결과 (Result)

- **성능 비약적 향상**: 수백만 명 대상의 복잡한 조건 연산이 수십ms 이내로 완료되어 어드민의 실시간성 확보.
- **저장 공간 효율**: 1,000만 명의 유저 데이터도 태그당 약 1.2MB 수준의 메모리로 관리 가능하여 매우 효율적인 역인덱스 인메모리 구축.
- **유연한 타게팅**: 수백 개의 태그 조합에 대해서도 성능 저하 없이 유연하게 타게팅 모수를 예측하고 설문을 배포할 수 있는 기반 마련.
